# MemorySaver

何日も起動したままのMacのための、メニューバー常駐アプリです。メモリを監視して、起動直後から大きく膨らんだアプリを見つけ、クリック1つで再起動します。

ファイルキャッシュのように、macOSが自分で手放せるメモリには手を出しません。実際に取り戻せるのは、長く動くうちに肥大したアプリが抱えているメモリで、取り戻すには通常そのアプリの再起動が必要です。MemorySaverは、どのアプリを再起動すると効果があるかを示します。

## 機能

- **メモリの概要**: 使用中のメモリ、メモリプレッシャー、スワップ、WindowServerのメモリを表示します。
- **アプリ別のメモリ**: 各アプリのヘルパープロセスを、アクティビティモニタと同じ方法でアプリにまとめて集計します。たとえばBraveのレンダラーはすべてBraveに含まれます。行をクリックすると、メモリの推移とプロセスの内訳が開きます。
- **再起動の提案**: 2GB以上を使っていて、かつ起動直後の1.5倍以上に増えたアプリについて、再起動を提案します。どちらのしきい値も設定で変えられます。
- **WindowServer**: ログイン時からの増加量と、原因になっていそうなウィンドウを持つアプリを表示します。
- **メモリの推移**: アプリやWindowServerの行をクリックすると、直近24時間または7日間のグラフを、基準値の線と一緒に表示します。
- **再起動はクリックしたときだけ**:
  - アプリを通常どおり終了させ（未保存の書類があればアプリが保存を確認します）、そのあと開き直します。
  - 強制終了はせず、勝手に何かを終了させることもありません。
  - Finder、Dock、loginwindowなどのシステムのプロセスは、一覧には出ますが再起動できません。
- **通知**: メモリプレッシャーが高く、再起動を勧めるアプリがあるときに通知します。
- **言語**: 日本語と英語に対応し、macOSの言語設定に従います。

## 動作環境

- macOS 14以降
- ビルドには、Swift 6を含むXcode、またはSwift 6のツールチェーン

## ダウンロード

[最新のリリース](https://github.com/hayato-ohya/memory-saver/releases/latest) からzipファイルをダウンロードして展開し、`MemorySaver.app` を「アプリケーション」フォルダに移動してください。Appleシリコン搭載のMac向けです。

このアプリはAppleの公証を受けていないため、初めて開くときにmacOSに止められます。次の手順で許可してください。

1. `MemorySaver.app` を開きます。「検証できません」という確認が出たら「完了」をクリックします。
2. 「システム設定 > プライバシーとセキュリティ」に表示されるMemorySaverについてのメッセージで「このまま開く」をクリックし、確認に答えます。

下の手順で、自分でビルドすることもできます。

## ビルドと起動

```sh
./scripts/make-signing-cert.sh   # 最初の1回だけ。macOSがパスワードを確認します
./scripts/bundle.sh install
```

`bundle.sh` はリリース版をビルドして `dist/MemorySaver.app` を作ります。`install` を付けると、さらに起動中のアプリを終了させ、`/Applications/MemorySaver.app` を置き換えて起動します。起動するとメニューバーに表示され、Dockには出ません。

`make-signing-cert.sh` は、自己署名の証明書「MemorySaver Dev」をログインキーチェーンに作ります。この証明書があれば `bundle.sh` はそれで署名するため、ビルドし直しても「ログイン時に起動」が使えたままになります。証明書がない場合はアドホック署名になり、ビルドし直すたびに「ログイン時に起動」が使えなくなります。

テストは次のコマンドで実行します。

```sh
swift test
```

## 仕組み

- **測定**: 1分ごとに、システム全体のメモリと、各プロセスのメモリ使用量（アクティビティモニタの「メモリ」と同じ値）を読み取ります。
  - WindowServerは別ユーザーで動いているため、`/usr/bin/top` を使って読み取ります。いちばん負荷が高い処理なので、5分ごとにしています。
- **基準値**: 履歴は7日分を保存します。アプリの基準値は起動後5〜20分の標準的な大きさ、WindowServerの基準値はログイン直後の大きさです。
  - MemorySaverを起動する前から動いていたアプリは、再起動されるまでのあいだ、最初に測った時点の大きさを基準にします。
- **WindowServerの原因候補**: ウィンドウの大きさから推定した値です。WindowServerのメモリをアプリ別に分ける公開された方法は、macOSにはありません。

## プライバシー

- MemorySaverはネットワークに接続しません。
- 記録するのはアプリごとのメモリ量と測定時刻だけで、Mac内の `~/Library/Application Support/MemorySaver/history.sqlite` に保存します。
- 読み取るのはプロセス名とメモリ量です。ウィンドウのタイトルや内容は読まないため、画面収録の許可は不要です。

## 制限事項

- **WindowServer**: メモリを直接解放する方法はありません。原因候補のアプリを再起動すると減ることがあり、ログアウトすれば必ず起動時の大きさに戻ります。
- **`top` による読み取り**: WindowServerの値は `top` の出力形式に依存するため、将来のmacOSでこの値だけ読めなくなる可能性があります。その場合も、ほかの機能は動き続けます。
- **ログイン時に起動**: macOSはアプリの場所と署名でログイン項目を見分けます。アプリは「アプリケーション」フォルダに置いてください。自分でビルドする場合は、`make-signing-cert.sh` で作った証明書で署名してください。アプリが「アプリケーション」フォルダの外にあるときや、システム設定でログイン項目がオフになっているときは、設定画面に警告が出ます。

## 言語の追加

画面の文言は `Sources/MemorySaverCore/Resources/<言語コード>.lproj/` にあります。`en.lproj` を言語コードの名前のフォルダ（例: `fr.lproj`）にコピーし、2つのファイルの値を翻訳してください。コードの変更は不要です。

`swift test` で、すべての言語に全文言がそろっているか、埋め込む値が一致しているかを検査できます。
